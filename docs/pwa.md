# PWA 安装、缓存与更新

## 使用

- 在 HTTPS 网站首次联网打开，浏览器会准备独立新版的离线界面。
- Chrome / Edge 等支持的浏览器可以通过地址栏或菜单安装。
  浏览器提供安装事件时，设置中的“安装与更新”也会出现“安装应用”。
- iPhone / iPad 在 Safari 的分享菜单中选择“添加到主屏幕”。
- 安装图标沿用现有音箱轮廓；`public/icons/app.svg` 是源图，192 / 512 PNG
  适配普通与 maskable 图标，180 PNG 用于 Apple 主屏幕。网页 favicon 保持不变。
- 离线可以打开界面；控制音箱、搜索和获取音乐数据仍需网络。
  PWA 不提供后台设备服务，也不解除 HTTPS 网页连接 `ws://` 的浏览器限制，
  HTTPS 连接方式仍按主 README 的 WSS 反向代理说明配置。

## 更新行为

- 每次联网打开，浏览器检查 Service Worker；也可在设置中手动“检查更新”。
- 新资源完整下载后显示“更新并重新加载”。用户点击前不强制激活或刷新；
  关闭所有旧页面后，浏览器也可自动启用已准备好的版本。
- 点击更新仅重新加载当前窗口，不强制刷新其他正在控制音箱的窗口。
  当前控制连接会短暂断开，重载后按已有连接恢复逻辑重新连接。
- 偏好与设备地址仍在 localStorage，不因应用缓存更新而清除。
- 下载任意必要资源失败时，放弃新缓存，原已安装版本仍可离线使用。

## 维护与范围

- 无需运行 Node 服务；`npm run build` 后仍是 GitHub Pages 可部署的静态文件。
- `public/site.webmanifest` 的 `id`、`scope` 和 `start_url` 使用相对路径，
  注册地址相对于实际应用目录，兼容自定义域名根目录和 `/仓库名/` 子目录。
- `scripts/build-pwa.mjs` 读取正式构建的 HTML、清单、图标及 `_app/` 资源，
  对文件内容与策略模板计算版本，输出 `dist/service-worker.js`。不要直接编辑生成文件。
- HTML 导航优先联网，主机不可达时回退完整的已安装界面；已知静态资源使用版本缓存。
  不将新 HTML 写进旧构建缓存，避免旧缓存与新资源混合。
- 预缓存请求逐文件校验 SHA-256；即使发布切换中 HTTP 请求成功但内容来自另一版本，
  也会放弃本次安装，保留原已安装版本。
- 只接管应用入口与自身静态资源的缓存读取。API、音频、WebSocket、设备代理、
  POST 请求及 `/upstream/` 页面均直接交给网络，不纳入离线缓存。
- 缓存名包含部署路径与构建版本；只清理本应用在该路径的旧缓存，保留当前和上一版，
  不清理其他应用或原作者版的缓存及注册。
- `tests/test_pwa.py` 用真实 Chromium Service Worker 覆盖根目录／子目录安装清单、
  离线重开、接口与原作者页面排除、等待用户更新、多窗口、缓存隔离及失败回退。
  `tests/test_new_web.py` 另外验证安装按钮调用浏览器提供的安装事件。
